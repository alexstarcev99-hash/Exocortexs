# ML-инженер — Roadmap самостоятельного обучения

**Статус:** Активный, самостоятельное обучение (ментор — по решению, если движение застопорится)
**Цель:** Junior/Middle ML-инженер за 12 месяцев
**Темп:** 20ч/неделю (~1040ч за год)
**Отличие от `ai-engineering-roadmap.md`:** тот файл — про работу с LLM через API (RAG, агенты). Этот — про классический ML-инженер: математика, Python для данных, обучение моделей, деплой. Разные профессии на рынке труда, пересечение частичное. Прогресс из старого файла (Python/API, неделя 1) переносится сюда как база — не теряется.

## Фаза 1. Математика + Python для данных (Месяц 1-2)

### Математика (параллельно с Python, не последовательно)

**Линейная алгебра:**
- 3Blue1Brown, «Essence of Linear Algebra» (YouTube, бесплатно) — интуиция прежде формул
- Практика: векторы, матрицы, умножение матриц, собственные значения — на бумаге + numpy

**Статистика и вероятность:**
- StatQuest with Josh Starmer (YouTube) — объясняет статистику для ML понятнее учебников
- Ключевые темы: распределения, мат. ожидание/дисперсия, корреляция, байесовская вероятность

**Матанализ (минимум для ML):**
- 3Blue1Brown, «Essence of Calculus» — только интуиция производной и градиента, без строгих доказательств

**Результат:** Понимаете, что происходит «под капотом» у градиентного спуска и метрик, не только как вызвать функцию.

### Python для данных

**У вас уже есть:** базовый Python + работа с Anthropic SDK (из старого roadmap, неделя 1) — не начинаете с нуля.

**Добавить:**
- NumPy, Pandas — Kaggle Learn (бесплатные короткие курсы: Python, Pandas, Data Visualization)
- Matplotlib/Seaborn — визуализация данных

**Практика:**
- Взять любой открытый датасет (Kaggle) — загрузить, почистить, визуализировать распределения
- Цель — свободно двигаться в Pandas, не гуглить каждую операцию

**Критерий готовности к Фазе 2:** можете самостоятельно загрузить сырой датасет, привести к чистому виду и построить 3-5 базовых графиков без подсказок.

## Фаза 2. Классический ML (Месяц 3-4)

**Курс-основа:** Andrew Ng, Machine Learning Specialization (Coursera/deeplearning.ai) — стандарт отрасли, даёт математику и интуицию одновременно.

**Книга-опора:** «Hands-On Machine Learning with Scikit-Learn, Keras & TensorFlow» (Aurélien Géron) — практическая, с кодом на каждую тему.

**Темы:**
- Supervised learning: линейная/логистическая регрессия, деревья решений, random forest, gradient boosting (XGBoost)
- Unsupervised learning: кластеризация (k-means), понижение размерности (PCA)
- Оценка моделей: train/val/test split, cross-validation, метрики (accuracy, precision/recall, ROC-AUC, RMSE)
- Feature engineering, overfitting/underfitting, регуляризация

**Практика:** 2-3 законченных мини-проекта на реальных датасетах (Kaggle) с полным циклом: данные → фичи → модель → метрики → выводы.

**Критерий готовности к Фазе 3:** можете взять новый табличный датасет, самостоятельно построить и оценить 2-3 модели, объяснить выбор метрики.

---

## Фаза 3. Deep Learning (Месяц 5-7)

**Курс-основа (выбрать один):**
- fast.ai, «Practical Deep Learning for Coders» — code-first, быстрее к результату
- deeplearning.ai, Deep Learning Specialization (Andrew Ng) — глубже в теорию

**Фреймворк:** PyTorch (официальные туториалы pytorch.org) — стандарт в индустрии и в вакансиях чаще, чем TensorFlow.

**Темы:**
- Нейросети с нуля: forward/backward pass, функции активации, loss-функции
- CNN (изображения), RNN/трансформеры (текст) — на уровне «понимаю и применяю», не «изобретаю архитектуру»
- Transfer learning — дообучение готовых моделей (практично для портфолио)
- Тренировка на GPU (Google Colab бесплатно, или Kaggle Notebooks)

**Практика:** 2 проекта — один по изображениям (классификация), один по тексту (используя опыт из старого roadmap — там уже есть работа с LLM API).

**Критерий готовности к Фазе 4:** можете дообучить готовую модель под свою задачу и объяснить, что происходит на каждом шаге пайплайна.

## Фаза 4. Специализация + портфолио (Месяц 8-10)

**Выбрать 1 специализацию** (не распыляться — тот же принцип TOC, что и везде в вашей практике):
- NLP/LLM-приложения — синергия со старым roadmap (RAG, агенты) и с личным брендом
- Computer Vision
- Классический ML/MLOps (продакшн, деплой моделей)

**Портфолио — 3-4 законченных проекта на GitHub:**
- Каждый — полный цикл: постановка задачи → данные → модель → оценка → деплой (хотя бы простой — Streamlit/FastAPI)
- README с чётким описанием, метриками, выводами — это то, что реально смотрят рекрутеры
- Минимум один проект — публичный, с живым демо (Hugging Face Spaces / Streamlit Cloud, бесплатно)

**Синергия с личным брендом:** каждый проект — материал для поста (документирование пути, уже выстроенная механика).

## Фаза 5. Подготовка к трудоустройству (Месяц 11-12)

- Резюме под ML-инженера (не под ИИ-инженера — разные ключевые слова для ATS/рекрутеров)

- Активный поиск удалённых вакансий, синхронизация с целью «высокооплачиваемая удалённая работа»

## Когда нанимать ментора — явные критерии

Раз решили пробовать самостоятельно, вот сигналы, что пора остановиться и нанять (не полагаться на ощущение «наверное, стоит»):

- Застряли на одной теме **больше 2 недель** без измеримого прогресса
- Не можете самостоятельно продиагностировать, почему модель не работает (баг vs. концептуальная ошибка)
- Нет обратной связи по качеству портфолио-проектов — не с кем свериться, соответствует ли уровень junior/middle
- Подготовка к собеседованиям буксует без внешней проверки (mock-интервью)

Это те же критерии остановки, что использовались в психологической защите финансовой системы — не «стыдно просить помощь», а операциональный сигнал, а не настроение.

## Еженедельный ритм (структура 20ч)

Переиспользую формат из старого roadmap — он рабочий:

- **Понедельник:** планирование (30 мин) — что изучаю, что практикую на неделе
- **Вт-Пт:** обучение + практика (~16ч) — 40% теория/курс, 60% руки в коде
- **Выходные:** рефлексия + документирование (~3.5ч) — weekly report, обновление прогресса, материал для поста в ТГ
